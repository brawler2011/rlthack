# Концепция и архитектура решения: Хакатон Росэлторг (СПб)

Интеллектуальный сервис поиска релевантных поставщиков, производителей и дистрибьюторов для АИС ГЗ и электронного магазина Санкт-Петербурга.

---

## 1. Суть кейса и критерии оценки

**Целевой сценарий:** по данным закупки сформировать ранжированный список потенциально релевантных контрагентов.

### Критерии оценки (всего 100 баллов):
1. **Работоспособность и целостность решения (30 баллов)** — сквозной пайплайн, стабильная работа без ошибок, готовность к демонстрации.
2. **Качество рекомендаций (25 баллов)** — релевантность контрагентов предмету закупки, ОКПД2, ценовому сегменту и истории участия/побед.
3. **Обогащение и расширение пула (25 баллов)** — привлечение новых компаний вне исходного датасета, классификация ролей (*Производитель / Дистрибьютор / Поставщик*), достоверность обогащенных данных.
4. **Объяснимость результата / XAI (10 баллов)** — прозрачность рекомендаций (почему поставщик в топе, почему присвоен статус).
5. **Интерфейс и UX (10 баллов)** — удобство веб-сервиса для специалистов по закупкам.

> **КРИТИЧЕСКОЕ ОГРАНИЧЕНИЕ:** Запрещается использование внешних API нейронных сетей (OpenAI, Claude, DeepSeek, облачные LLM). Все ML-модели и вычисления должны выполняться строго локально.

## 2. Архитектура и стек технологий

### Фронтенд: Web на React (Vite + Tailwind / Shadcn UI / Ant Design)
* **Почему не нативное приложение:** на защите жюри не будет ставить `.exe` или `.apk`. Необходим веб-сервис, доступный в браузере с адаптивным дашбордом закупщика АИС ГЗ.
* **Ключевые экраны:**
  - Поиск/выбор закупки из базы или ввод параметров новой закупки.
  - Ранжированная таблица поставщиков с фильтрами по ролям (*Производитель / Дистрибьютор*), региону (СПб/ЛО) и МСП.
  - Детальная карточка контрагента с факторами объяснимости (Explainable AI) и историей поставок.

### Бэкенд: Python (FastAPI + Pydantic + Uvicorn)
* Высокая скорость асинхронной обработки запросов.
* Автодокументация Swagger/OpenAPI.
* Прямая интеграция с локальными Python ML-библиотеками.

### Хранилище и быстрый аналитический слой: DuckDB / SQLite / PostgreSQL
* Исходные датасеты содержат свыше 4.5 млн строк (ТРУ — 2.97 млн, Поставщики — 1.01 млн, Извещения — 604 тыс.).
* DuckDB позволяет выполнять SQL-агрегации и аналитику по миллионам записей за десятки миллисекунд прямо в оперативной памяти.

## 3. Как решение должно работать: Real-time vs Batch

Система работает по **двухфазной схеме (Offline Precomputation + Fast Real-Time Inference)**:

```
[4.5 млн строк истории] 
          ↓ (Offline за 2-3 минуты один раз)
[Векторный индекс + Агрегированные профили поставщиков]
          ↓
[FastAPI Backend: Real-time поиск за 300 мс] ← [Пользователь в React UI]
```

1. **Оффлайн/Фоновый этап (Precomputation):**
   * Единоразовая предобработка датасета: расчет агрегированных профилей поставщиков по ИНН (WinRate, суммарный объем, распределение чеков, перечень ОКПД2, активность за 2024–2025 гг.).
   * Построение легковесных индексов поиска (BM25 + эмбеддинги).
   * Обогащение реестрами (ОКВЭД, роли).
2. **Онлайн-этап (Real-Time отклик за 200–500 мс):**
   * При вводе параметров или выборе лота закупщик мгновенно получает ранжированный список топ-10/20 контрагентов.
3. **Бизнес-сценарий фонового режима (Batch) для презентации:**
   * Помимо интерактивного UI, система поддерживает фоновый робот: ежедневный автоматический подбор поставщиков под свежеопубликованные извещения и рассылка персональных приглашений на торги.

## 4. Что делать по ML и алгоритмам

### А. Этап отбора кандидатов (Candidate Retrieval)
* **Иерархический фильтр по ОКПД2:** сопоставление по точному коду и родительским группам (2, 4, 6 знаков).
* **Гибридный текстовый поиск:**
  - Лексический поиск **BM25** по наименованиям ТРУ и предмету закупки.
  - Локальный семантический векторный поиск (**`cointegrated/rubert-tiny2`**).

### Б. Модель ранжирования (Scoring / Reranking)
Ранжирование кандидатов с помощью взвешенной модели скоринга / CatBoost Ranker на основе признаков:
* **Текстовое сходство:** косинусное расстояние между вектором закупки и профилем ТРУ контрагента.
* **Надежность и опыт поставщика:**
  - $\text{WinRate} = \frac{\text{Победы}}{\text{Участия}}$
  - Общее число исполненных контрактов.
  - Средняя сумма контракта поставщика относительно НМЦК текущей закупки.
  - Свежесть активности (контракты в 2024–2025 гг.).
* **Логистический фактор:** приоритет поставщикам СПб и Ленинградской области (коды ИНН/КПП 78, 47).
* **Соответствие критерию СМП (`is_smp`).**

### В. Классификация ролей: Производитель / Дистрибьютор / Поставщик (25 баллов)
* **Производитель:** ОКВЭД раздела «C» (Обрабатывающие производства, коды 10–33) + реестр промышленной продукции Минпромторга (ГИСП).
* **Дистрибьютор / Оптовик:** ОКВЭД раздела 46 («Торговля оптовая...»).
* **Поставщик широкого профиля:** ОКВЭД 47, разнородные закупки в истории поставок.

## 5. Библиотеки для ML (локальные, без внешних API)

* `sentence-transformers` + модель `cointegrated/rubert-tiny2` (45 МБ, быстрый инференс на CPU).
* `rank-bm25` — лексический BM25-поиск по ТРУ.
* `catboost` / `scikit-learn` — табличный скоринг и ранжирование.
* `rapidfuzz` — нечеткое сопоставление номенклатуры, брендов, артикулов.
* `polars` / `duckdb` — высокопроизводительный процессинг датасетов.
* `pymorphy3` + `nltk` — лемматизация русскоязычных наименований закупок.

## 6. Обогащение данных (25 баллов) и открытые источники

1. **Реестры ФНС / ЕГРЮЛ (по ИНН):**
   * Официальные наименования компаний, статус (действующая / ликвидация).
   * Основной и дополнительные коды ОКВЭД (основа для классификации ролей).
   * Выручка, масштабы бизнеса.
   * Проверка на отсутствие в Реестре недобросовестных поставщиков (РНП).
2. **Реестр Минпромторга (ГИСП):**
   * Статус официального отечественного производителя для импортозамещения.
3. **Поиск новых поставщиков из открытых источников:**
   * Парсинг / поиск по номенклатуре в каталогах продукции, реестрах поставщиков СПб, открытых справочниках с извлечением ИНН новых организаций.

## 7. Объяснимость (Explainable AI — 10 баллов)

В UI в карточке каждого рекомендованного контрагента отображается блок «Почему рекомендован»:
* **Роль:** Производитель (подтверждено ОКВЭД 28.25 и реестром Минпромторга).
* **Опыт в аналогичных ТРУ:** 15 исполненных контрактов (WinRate: 72%).
* **Финансовый масштаб:** средний чек соответствует бюджету закупки.
* **Регион:** Санкт-Петербург (КПП 78...).
* **Фактор благонадежности:** 0 записей в РНП, действующий статус ФНС.

## 8. Пошаговый план разработки

| Этап | Задача | Результат |
| :--- | :--- | :--- |
| **1. Data Pipeline** | Агрегация данных по ИНН (DuckDB/Polars), расчет WinRate, объемов, чеков, ОКПД2-профилей | Быстрый файл базы данных / витрины профилей |
